# Transit V12 apples-to-apples result — 2026-09-16

Target: real Qwen `blk.0.ffn_gate.weight`, correct GGUF/GEMV geometry `9216 output rows x 2560 input columns`, Q4_K x Q8_K, single thread, i5-12500H laptop, 16 GB DDR5-4800.

The comparison was intentionally narrowed to the current llama-style AVX2 baseline versus the V15 `x8meta` runtime representation. The benchmark interleaves the two kernels and alternates order each iteration to reduce turbo/order bias. It reports both hot-cache and explicit 64 MiB eviction regimes.

## Normal `-O3 -march=native`

- HOT: llama median `1.228 ms`, x8meta median `1.071 ms`, paired speedup `1.094x`, best `0.828 / 0.840 ms`.
- EVICTED: llama median `1.295 ms`, x8meta median `1.174 ms`, paired speedup `1.032x`, best `0.952 / 0.975 ms`.

## `-fno-unroll-loops`

- HOT: llama median `1.313 ms`, x8meta median `1.165 ms`, paired speedup `1.115x`, best `0.925 / 0.955 ms`.
- EVICTED: llama median `1.304 ms`, x8meta median `1.169 ms`, paired speedup `1.110x`, best `0.936 / 0.983 ms`.

## Decision

`x8meta` wins all four paired comparisons. The result that matters most for the active implementation track is the no-unroll build, where the gain is stable across cache states: about `+11.5%` hot and `+11.0%` after explicit cache eviction.

This supersedes the earlier interpretation of the V15 `1.403x` figure. That older figure compared x8meta to a slower internal packed-control kernel, not to the current llama-style AVX2 baseline. The validated claim is therefore approximately 1.1x at this operator on the current laptop, not 1.4x.

The runtime representation still preserves the original Q4 nibbles and FP16 `d/dmin` values and costs approximately `+2.78%` runtime weight storage. No additional model quantization is introduced.
